# Validation and interpretation

CPU tests run with `.venv/bin/python -m pytest tests`. They exercise DPM++ 2M against a separately written log-time midpoint recurrence across 2, 3, 20 and 100 steps with a changing analytic denoiser. They also verify deterministic PCG64 float32 noise, layout round trips, dimensions, request bounds and actual local CLIP tokenization (77 positions, negative/positive CFG order, truncation). No GPU or network download is needed. These checks validate the sampler algebra and input contract; they do not prove every GPU kernel matches a reference.

Use `.venv/bin/python summarize.py --baseline NAME.json --output benchmark/summary.json` to summarize existing runs without generating images. Baseline names must be exact. Mismatched request, model path, sampler, schedule, RNG, precision or quantization disables the matched speedup calculation. The model path is not a checksum: model provenance must still be preserved.

Cold means the first image after loading the model in a process, including kernel warmup. It does not mean the operating-system file cache was cleared. Model load is separate. Legacy `total_time` is a sum of stage timers, not full user-visible latency: latent initialization, intermediate saving and final normalization fall outside it. PNG saving is separate. Schema `generation-wall-v2` fixes this: `total_time` is full generation wall time less measured diagnostic `.npy` transfer/save time, including latent initialization and postprocessing; `wall_time` includes diagnostics; `stage_sum_time` preserves the named component sum. The summarizer suppresses total-time speedups between timing schemas. Diffusion-stage comparisons remain available. Model loading and PNG encoding remain separate. A repeated warm run in one process is not an independent experimental session. Results with a single warm sample must not be described as statistically established speedups. Collect several separate sessions in alternating order, with matching requests and no concurrent GPU generation, before presenting confidence intervals.

The MPS baseline is a matched custom pipeline using the same SD1.5 weights, shared NumPy PCG64 noise, Karras rho=7 schedule, DPM++ 2M recurrence, CLIP tokenization and nominal precision. It is not AUTOMATIC1111 end-to-end performance. UNet/CLIP use fp16, VAE/latents use fp32. Different backends may still choose different internal accumulation and attention implementations.

The initial cross-backend comparison (`quality-mps-mlx.json`) records PSNR 51.1427 dB, SSIM 0.9984797 and pixel MAE 0.0013696 for one 512×512 seed/prompt pair. Conditioning relative L2 error is 0.0017217 and final latent relative L2 error is 0.0055892. These support close agreement for this example only; they do not validate later attention, compile or quantization changes. Re-run comparisons against every selected candidate, across representative prompts and seeds, and inspect the images for semantic or fine-detail differences. Quantized output must be evaluated separately.

`buffer_reuse` caches immutable timestep/coefficient metadata. It does not implement a persistent pool of UNet activation tensors. MLX owns physical activation allocation and allocator caching. RSS and GPU allocation overlap in unified memory and must not be added. Missing power, temperature, frequency and utilization values are unavailable measurements, not zero. System-wide swap already present before a run is not attributable solely to that run.
